# Privacy Policy - Issue Hierarchy Tree

**Effective date:** 10.09.2026

**Contact:** bim.eleck@gmail.com

## Summary

Issue Hierarchy Tree ("the App") does not process or store End-User Data outside of Atlassian's own apps and services. The App runs entirely on Atlassian's infrastructure (Forge) and is eligible for Atlassian's **Runs on Atlassian** program.

## What the App accesses

When you open the App's panel on a Jira issue, it reads the following — using **your own logged-in Jira permissions**, so the App never sees more than you could already see in Jira:

- Issue key, summary, status, and issue type
- Parent/child hierarchy relationships
- Issue links of type "blocks" / "is blocked by" (including the linked issue's summary and status)

The App does not access comments, attachments, custom fields beyond the above, or any user profile data (name, email, avatar).

## How data is handled

- **No storage**: the App does not use a database or any persistent storage (no Forge Storage, no external database). Each panel load fetches fresh data and discards it once rendered.
- **No external transmission**: no data is sent to any server outside Atlassian's infrastructure. There are no analytics, tracking, or advertising integrations.
- **No REST APIs provided**: the App does not expose any API of its own for third parties to call.
- **No data residency options**: not applicable, since no End-User Data is stored by the App outside Atlassian.

## GDPR / CCPA

Because the App does not collect, store, or retain personal data outside of Atlassian's own systems, **IE Andrei Danilchankau** does not act as a data controller under GDPR or as a business/service provider under CCPA with respect to End-User Data processed through the App. Atlassian's own data processing terms govern data hosted on the Jira platform itself — see [Atlassian's Privacy Policy](https://www.atlassian.com/legal/privacy-policy).
